# Power BI 图表资源导航站设计规格

## 目标

建设一个中文优先、可部署到 Qoder Sites 的 Power BI 可视化资源导航站。用户可以按名称、类别和关键词查找图表，查看来源描述与链接，并跳转到商店、示例或原始下载页面。管理员/站点用户可在线手动触发目录同步，查看同步时间与变更概览。

## 已确认的产品边界

- 中文界面、分类、筛选与功能标签；官方图表名称和描述保留来源语言，第一阶段不调用翻译服务或承诺中文摘要。
- 第一阶段重点为检索、筛选和资源链接；不做用户账号、收藏跨设备同步、评论或商业化。
- 站点最终部署到 Qoder Sites。
- 在线“检查更新”通过站点后端函数调用来源并更新数据库。
- DataChant 的 PowerBI-Visuals-Marketplace 仓库为批量清单和下载链接主来源。
- Microsoft Marketplace 与 OKVIZ 是产品详情、授权和编辑性信息的外链/可选补充来源；不依赖未确认的公开 API 或脆弱的全站爬取。
- 不镜像/重新分发第三方 PBIVIZ、PBIX 或厂商图片。资源按钮跳转到来源原地址；许可与使用条款优先展示发布者信息。
- 用户已选择更新方式为线上手动触发，而非本地同步后重新发布。

## 页面体验

### 目录页

- 自适应桌面与移动浏览器宽度；宽屏采用侧栏 + 主目录，窄屏折叠侧栏并重排搜索、筛选和卡片。
- 搜索名称、发布者、原文描述与关键词。
- 筛选类别、价格模型、微软认证、是否含 PBIX 示例、来源等可用字段；对来源未提供的字段不伪造值。
- 以卡片展示名称、发布者、来源描述（原文）、中文类别/功能标签、价格与认证状态（若有）、评分与来源更新时间（若有）。
- 卡片提供商店详情、发布者页面、PBIVIZ/PBIX 样例/下载链接（若数据源确实提供）等外链。
- 显示最后成功同步时间、数据来源和当前结果数量。

### 详情呈现

第一阶段可通过站内详情抽屉或详情区域呈现完整记录：来源描述原文、版本、发布者、分类、价格/认证/评分（字段存在时）、法律条款/隐私/支持链接、商店链接、示例与下载来源链接。不得把未知值显示为事实。

## 数据与同步架构

### 组件

1. Qoder Sites 前端：目录检索、筛选、分页/增量渲染、详情展示和同步状态。
2. Qoder Sites 数据库：存储规范化后的可视化目录与同步运行记录。
3. Qoder Sites 后端函数：受控读取 DataChant 的公开清单，解析、校验、标准化、去重并写入数据库。
4. 上游来源：DataChant GitHub 仓库作为批量基线；Marketplace 和 OKVIZ 保存为逐条来源链接及可选手工补充信息。

### 主数据同步流程

- 用户点击“检查更新”后，前端调用后端同步函数。
- 函数读取 DataChant 的公开 CSV/元数据，记录实际获取时间与上游提交/版本标识（源数据提供时）。
- 将记录映射到统一模型，以稳定 ID/Visual GUID/源 ID 优先去重；保留上游原值和原始来源 URL。
- 校验必需字段和 URL 协议，只允许 HTTP(S) 外链；异常记录进入失败统计，不得清空或覆盖现有有效目录。
- 采用事务或等效原子更新策略，全部校验后提交，避免同步中断造成半套数据。
- 保留最近一次成功数据；同步失败时不改变当前目录数据，显示可读错误与失败时间。
- 返回新增、更新、移除/下架及跳过数量；下架记录应优先标记状态，不立即物理删除，避免上游短暂缺失导致数据丢失。
- 不自动抓取 Marketplace/OKVIZ 的 HTML 页面；这两类来源仅保存稳定详情链接和已有可用字段。若未来需要自动补充，单独评估合法性、稳定性与接口许可。

### 建议数据模型

`visuals`：稳定主键、源 ID、Visual GUID、名称、发布者、原始描述、类别、关键词、版本、价格模型、认证状态、评分/评分数、图标 URL、商店 URL、发布者 URL、PBIVIZ/PBIX 外链、法律条款/隐私/支持链接、来源、首次发现时间、最后发现时间、上游更新时间、状态、原始数据 JSON。

`sync_runs`：运行 ID、开始/结束时间、状态、上游标识、读取/新增/更新/下架/跳过/失败数量、可展示摘要和错误摘要。

具体字段类型及索引在读取 Qoder Sites 当前数据库 API 后确定；只为目录搜索与过滤建立必要索引。

## 语言策略

- 导航、筛选、类别、状态和操作界面使用中文。
- 图表官方名称、发布者名称与产品描述保持来源原文；中文类别标签由本地映射表提供。
- 第一阶段不翻译描述、不调用翻译 API，也不展示伪造或推测的中文摘要。后续若需要机器翻译，应单独评估服务、费用、密钥和翻译质量，并保留原文。

## 错误与安全边界

- 同步函数只访问配置的 DataChant GitHub 来源，不接受任意用户 URL，避免 SSRF。
- 校验外链为 HTTP(S)，渲染外部描述时按纯文本处理，防止注入脚本或 HTML。
- 同步操作设置合理超时、响应大小/记录数边界，并提供重复请求保护；函数凭据仅存放在 Sites Secret，不进入前端代码。
- 未授权状态下不得触发写数据库同步；在确认 Qoder Sites 身份/访问控制能力之前，保持同步操作受平台权限保护，必要时只允许站点所有者执行。
- 透明标注第三方数据的来源、最后同步时间、授权链接和数据可能过期。

## 部署与运维

- 使用 Qoder Sites 提供的前端、后端函数、数据库与 Secret 能力；发布前验证预览/正式发布流程和所需权限。
- 初始数据由同一同步函数导入，避免维护两套导入路径。
- 暂不设置定时触发器；由用户手动点按触发。同步历史可在站内查看最近记录。
- 若 Qoder Sites 环境不支持所需网络访问、数据库事务或站点访问控制，停止发布前置操作并调整架构，不以静态假数据伪装成已同步目录。

## 验收标准

1. 目录在宽屏、平板和手机视口下均可浏览，无固定宽度溢出；搜索与筛选在窄屏仍可使用。
2. 搜索能匹配图表名、发布者、摘要及关键词；组合筛选结果正确，并有清晰空结果状态。
3. 目录记录中的商店/样例/下载入口能指向对应来源；无来源的字段不出现虚构链接或值。
4. 首次同步和重复同步可成功；重复运行不产生重复视觉记录，并能报告新增/更新/下架统计。
5. 上游不可达、格式异常或部分记录无效时保留最近一次成功数据，并在 UI 显示失败状态。
6. 同步状态展示最近运行时间与结果摘要；并发重复触发受控。
7. 访问控制阻止未授权用户触发同步写入；前端不暴露秘密凭据。
8. 不把第三方视觉、PBIX 或图片文件复制到本项目或站点存储。

## 实施前置核验

正式实现前，使用 Qoder Sites 当前工具确认：站点/项目创建与上下文、数据库 schema/migration、函数调用与日志、Secret、预览和发布流程、站点访问策略。此规格不假定 Qoder Sites 工具或运行时支持尚未验证的接口。
